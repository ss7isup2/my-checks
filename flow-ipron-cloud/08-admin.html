관리 화면은 탭이 페이지 역할을 합니다

사용자 관리, 권한, 공통 코드, 캠페인, 평가, 통계처럼 화면이 많은 쪽은 front/src/pages/tabs에 있습니다. 브라우저 주소를 화면마다 만들지 않고, 한 페이지 안에서 탭으로 겹쳐 엽니다.

껍데기

layouts/MainLayout.vue 구조는 이렇습니다.

  • FlowHeader — 위쪽. 티켓 보드 숫자를 받아 아래로 넘깁니다.
  • FlowQuickMenu — 메뉴 진입.
  • pages/MainPage.vue — 열린 탭과 탭 내용. 높이는 헤더·푸터를 뺀 값으로 맞춥니다.
  • FlowFooter — 아래. 티켓 보드 카운트를 표시합니다. 10초 웹소켓과 연결되는 자리입니다.

Quasar 레이아웃 뷰 문자열은 hHh LpR lFf입니다. 헤더 고정, 본문, 푸터 고정이라는 뜻으로 보면 됩니다.

탭이 열리는 코드

pages/MainPage.vue는 두 조각입니다.

  1. useMainTabStore()의 tabs, activeTab. 사용자가 연 메뉴 목록과 지금 보고 있는 탭 이름.
  2. components 객체. 키는 Menu.NOTICE.name 같은 문자열, 값은 defineAsyncComponent로 지연 로딩하는 Vue 파일.
const components = {
  [Menu.NOTICE.name]: defineAsyncComponent(() => import("pages/tabs/NoticeMain.vue")),
  [Menu.USER_MANAGE.name]: defineAsyncComponent(() => import("src/pages/tabs/UserManage.vue")),
  // ...
}

<FlowDynTabs v-model="mainTabStore.activeTab" :tabs="mainTabStore.tabs" @close="mainTabStore.closeTab" />
<q-tab-panels v-model="mainTabStore.activeTab" keep-alive>
  <q-tab-panel v-for="tab in mainTabStore.tabs" :name="tab.name">
    <component :is="components[tab.name]" />
  </q-tab-panel>
</q-tab-panels>

keep-alive라서 다른 탭으로 갔다가 돌아와도 검색 조건과 스크롤이 남습니다. 탭을 닫으면 스토어의 closeTab이 목록에서 빼므로 그때 컴포넌트가 사라집니다.

메뉴 이름의 정본은 front/src/js/common/menu.js입니다. 예를 들어 공지는 { name: "NOTICE", label: "공지사항" }입니다. 이 name이 서버 메뉴 코드, 탭 이름, components의 키, 세 곳과 같아야 화면이 나옵니다. 하나만 다르면 탭은 열리는데 내용이 빈 컴포넌트가 됩니다.

한 탭 파일의 전형적인 구성은 “검색 조건 ref → 조회 버튼에서 api 호출 → 표에 바인딩 → 행 선택 시 상세 → 저장 시 put/post”입니다. 표·입력·버튼은 components/common의 FlowDynTabs 형제들(FlowInput, FlowBtn, 그리드 래퍼)을 재사용합니다. 업무별 다이얼로그는 components/{업무}에 있습니다.

components 폴더를 업무로 찾기

front/src/components는 탭이 import하는 조각입니다. 폴더 이름이 백엔드 패키지와 거의 같습니다.

  • campaign — 대상자, 할당, 설문 팝업.
  • ticket, callback, call — 티켓 상세 팝업은 /popup/ticket-detail 라우트로도 열립니다.
  • users, permissions, menu, codes, organization.
  • evaluation, kms, notice, board, ums, statistic.
  • common — 업무와 무관한 입력, 표, 탭, 로딩.
  • layouts — TraditionalLayout, SingleViewLayout. 라우트의 UI 모드용 껍데기.

스토어가 탭보다 오래 삽니다

stores/mainTab.js가 탭 배열을 갖고 있으므로, MainPage가 다시 그려져도 열린 탭을 복원할 수 있습니다. 코드·조직·권한처럼 여러 탭이 같이 보는 데이터는 codeStore, organizationStore, permissionStore에 올려 두고, 첫 로드 이후에는 스토어를 읽습니다. 저장이 성공하면 스토어를 다시 load하거나 목록만 교체합니다. 화면만 고치고 스토어를 안 고치면, 다른 탭에 예전 코드 목록이 남습니다.

API 함수는 공유합니다. 칼럼 구성, 버튼 권한, 레이아웃은 각 Vue에 있습니다. 목록 쿼리를 바꾸면 js/api 한 곳과, 그 응답 필드를 읽는 두 Vue를 같이 확인합니다.

관리 화면에 메뉴를 하나 더 넣는 순서

  1. 백엔드 CRUD가 이미 있으면 URL을 js/api에 함수로 추가합니다.
  2. pages/tabs/SomethingManage.vue를 만들고 검색·표·저장을 연결합니다. 재사용할 입력은 components/common을 먼저 봅니다.
  3. js/common/menu.js에 name과 label을 추가합니다. name은 서버 메뉴 코드와 같게 합니다.
  4. MainPage.vue의 components에 그 name으로 지연 import를 넣습니다.
  5. 메뉴 관리 화면(또는 초기 데이터)에서 권한 그룹에 메뉴를 붙입니다. 프론트 맵만 있고 DB 메뉴가 없으면 사용자가 탭을 열 수 없습니다.
TraditionalLayout 자식과 혼동하지 않기 routes.js의 /traditional/campaigns 같은 항목은 pages/MainPage.vue를 placeholder로 가리킵니다. 캠페인 화면의 본체는 그 라우트가 아니라 pages/tabs/CampaignManagement.vue이고, 탭 스토어가 열어야 보입니다.
