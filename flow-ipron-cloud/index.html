이 문서는 코드를 같이 열어 보는 안내서입니다

WECOMS Flow Counsel은 컨택센터 상담·캠페인·설정 시스템입니다. 저장소 안에 백엔드가 두 패키지, 프론트가 두 화면 구조로 들어 있습니다. 처음 보면 폴더가 많아 보이지만, 반복되는 모양이 같습니다.

브라우저에서 이 파일(mydocs/index.html)을 열면 왼쪽 메뉴로 이동합니다. 서버가 없어도 됩니다.

오늘 이것만 기억해도 됩니다 화면은 Vue 파일을 부르고, Vue는 front/src/js/api로 REST를 호출합니다. 백엔드는 Controller → Service → DAO 순서로 내려가고, 로그인 사용자의 테넌트를 데이터에 붙인 뒤 DB에 저장합니다. 실시간 알림만 이 줄에서 빠져 웹소켓과 스케줄러를 탑니다.

읽는 순서

  1. 전체 지도 — 프로세스 하나 안에 백엔드 둘, 화면 둘이 어떻게 붙어 있는지.
  2. Controller · Service · DAO — 새 기능을 넣을 때 어떤 파일을 만드는지. 공지사항이 예시입니다.
  3. Flow 업무 묶음 — com.wecoms24.flow 패키지를 업무 이름으로 풀어 둔 표.
  4. Bridgetec 연동 — 상담사·조직·STT를 다른 DB에서 읽어 오는 쪽.
  5. 스케줄러와 웹소켓 — 매분 돌아가는 작업과, 브라우저로 밀어 주는 알림.
  6. 화면이 두 갈래인 이유 — 상담 화면과 관리 탭 화면.
  7. 상담 화면, 관리 탭 화면 — 각 화면의 폴더와 데이터 흐름.
  8. 공지로 한 바퀴 — 버튼 클릭부터 DB 저장, 다시 화면까지.
  9. 상담 화면 API, 관리 화면 API — 페이지·버튼이 부르는 주소와 백엔드 컨트롤러.
  10. API 전체 목록 — js/api 함수 582개를 URL과 컨트롤러로 펼친 표.

코드를 열 때 쓰는 말

말이 프로젝트에서 가리키는 것
엔티티DB 테이블과 1:1로 대응되는 Java 클래스. 예: Notice → 테이블 NOTICE.
SearchParameter목록 조회·등록 요청의 그릇. 안에 entity(본문)와 page, size, keyword가 들어갑니다.
DAODB에 실제로 쿼리하는 클래스. Flow 대부분은 JPA입니다. XML 매퍼는 Bridgetec·빌링에 있습니다.
테넌트고객사 하나. 거의 모든 행에 TENANT_EID가 있고, 다른 고객사 데이터는 보이지 않아야 합니다.
entityId그 행의 기본키. JSON에도 entityId라는 이름으로 나갑니다. 공지면 컬럼명은 NOTICE_EID입니다.
로그인 사용자JWT에서 꺼낸 User. 서비스 메서드의 첫 인자 loginUser가 그 사람입니다.

로컬에서 띄울 때

구분명령확인
백엔드 mvn spring-boot:run -Dspring.profiles.active=local 기본 포트 10211. Swagger는 /swagger-ui.html
프론트 cd front && npm install && npm run dev 개발 서버 포트 9000. 주소는 /{테넌트서브도메인}/login

프론트 개발 서버는 Quasar(Vue 3)입니다. API 주소는 front/src/boot/axios.js에서 만든 axios 인스턴스를 각 API 파일이 가져다 씁니다. 토큰은 localStorage의 accessToken을 Authorization: Bearer로 붙입니다. 붙이는 함수는 front/src/js/common/header.js의 getHeaders입니다.

문서를 읽을 때 한 가지 이 안내서는 저장소 소스를 읽고 정리한 것입니다. 스케줄러 중에는 @Scheduled가 주석 처리되어 지금 돌지 않는 것도 있습니다. 해당 페이지에 “지금 동작 / 코드만 있음”을 구분해 두었습니다.
