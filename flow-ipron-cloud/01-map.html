전체 지도

실행 파일은 Spring Boot 하나, 화면은 Quasar 앱 하나입니다. 그 안에 역할이 다른 코드가 나란히 들어 있습니다.

프로세스는 하나

시작 클래스는 com.wecoms24.flow.FlowApplication입니다. @SpringBootApplication(scanBasePackages = …)에서 두 패키지를 같이 스캔합니다.

  • com.wecoms24.flow — 상담, 티켓, 캠페인, 사용자, 권한, 알림. 우리 DB.
  • com.wecoms24.bridgetec — 브리지텍(아이프론 클라우드) SaaS DB를 읽는 연동. 다른 DataSource.

@EnableScheduling이 이 클래스에 있어서, @Scheduled가 붙은 메서드가 프로세스 안에서 주기적으로 실행됩니다.

백엔드 두 갈래

우리 업무 DB

flow

Java 파일이 약 1,000개입니다. 사용자·공지·티켓·캠페인처럼 “우리가 만들고 수정하는 데이터”가 여기 있습니다.

저장은 대부분 JPA입니다. Controller는 비어 있고, 부모 클래스 BaseWebCrudController가 등록·조회·수정·삭제를 제공합니다.

폴더: src/main/java/com/wecoms24/flow

외부 SaaS DB

bridgetec

Java 파일이 25개 정도입니다. 상담사 내선, 조직, 대표번호, STT 문장, 전광판 계정처럼 “브리지텍이 이미 갖고 있는 값”을 읽습니다.

MyBatis XML이 쿼리를 갖고 있습니다. CRUD 템플릿을 상속하지 않고, Controller에 @GetMapping을 직접 적습니다.

폴더: src/main/java/com/wecoms24/bridgetec

비슷해 보이는 이유 둘 다 URL은 /rest/api/v1/...이고, Controller가 요청을 받아 Service를 호출하고, Service가 DB 접근 객체를 부릅니다. 차이는 DB가 다르고, flow는 JPA 공통 부모를 쓰고 bridgetec은 Mapper XML을 쓴다는 점입니다.

DB가 두 개인 이유

상담 내용은 우리 스키마(티켓, 공지, 사용자)에 쌓입니다. 상담사의 내선번호, 그룹, STT 문장, 아웃바운드 잔여 시간은 브리지텍 계정 DB의 뷰·테이블에 있습니다. 그래서 FlowBridgetecDataSourceConfig가 HikariCP로 두 번째 DataSource와 MyBatis SqlSessionFactory를 만듭니다. 트랜잭션 매니저 이름도 다릅니다. Flow 서비스의 저장은 flowMainTransactionManager를 씁니다.
