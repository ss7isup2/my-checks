공지사항으로 요청을 끝까지 따라가기

새 기능을 읽을 때는 화면 파일 하나와 API 함수, 컨트롤러, 서비스, DAO를 한 줄로 이어 보면 됩니다. 공지는 그 줄이 짧습니다. 상담 화면과 관리 탭이 같은 API를 쓴다는 점도 여기서 확인됩니다.

1. 상담 화면에서 메뉴를 누른다

  1. 주소는 /{테넌트}/notices입니다.
  2. routes.js가 PostAuthLayout 안에 ipron/pages/NoticePage.vue를 넣습니다.
  3. 왼쪽 메뉴가 이 주소와 맞는 이유는 menuNamesStore의 NOTICES → /notices 맵입니다. 권한 API가 이 코드를 돌려줬을 때만 메뉴가 보입니다.
  4. 페이지는 NoticeSearchForm, NoticeTable, 등록 다이얼로그를 그립니다.

관리 탭에서 같은 데이터를 보려면 메뉴 코드 NOTICE로 탭이 열리고 pages/tabs/NoticeMain.vue가 그려집니다. 아래 API부터는 같습니다.

2. 목록 조회

front/src/js/api/noticeApi.js

const getNotices = (params) => {
  return api.get("/rest/api/v1/notice/notices", {
    params: { ...params, sort: "createdDate,desc" },
    ...getHeaders(),
  });
};

쿼리스트링 예: keyword=점검&page=0&size=20&sort=createdDate,desc. 헤더에는 Bearer 토큰이 있습니다.

  • 컨트롤러 자신은 메서드가 없습니다. BaseWebCrudController.getAllBySearchParam 또는, page·size·isPaging이 있으면 getByPaging이 선택됩니다. 스프링이 쿼리 파라미터가 있는 매핑을 더 구체적으로 봅니다.
  • 서비스 부모는 엔티티에 로그인 사용자의 테넌트를 넣습니다. 다른 고객사 공지는 WHERE에 걸리지 않습니다.
  • keyword가 있으면 DAO가 제목 또는 rawContent LIKE를 OR로 추가합니다.
  • 작성자 이름·아이디, 첨부 개수는 컬럼이 아니라 @Formula 서브쿼리입니다. USER_TM, FILE_METADATA를 조회 시점에 읽습니다.

응답은 배열이거나 Page JSON입니다. 포장 객체는 없습니다. 화면은 response.data 또는 response.data.content를 표에 넣습니다.

3. 한 건 등록

api.post("/rest/api/v1/notice/notices", param, getHeaders());

param은 엔티티 단독이 아니라 검색조건 모양입니다.

{
  "entity": {
    "title": "점검 안내",
    "content": "<p>본문</p>",
    "rawContent": "본문"
  }
}

postByMessage가 entityParam.getEntity()만 서비스에 넘깁니다. 서비스는 테넌트를 채운 뒤 DAO create를 호출하고, 트랜잭션은 flowMainTransactionManager입니다. 생성자·생성시각은 Auditing이 채웁니다. 응답은 저장된 Notice JSON이고, 그 안의 entityId가 NOTICE_EID입니다.

4. 상세와 첨부

GET /rest/api/v1/notice/notices/{entityId}는 NoticeServiceImpl.findOne이 부모 조회 뒤에 첨부를 붙입니다.

  • FileMetaDataDao.findAllByResourceTypeAndResourceKey("notice", entityId)
  • 결과를 notice.files에 넣습니다. 이 필드는 @Transient라 공지 테이블 컬럼이 아닙니다.
  • 파일 자체의 업로드 URL은 공지 컨트롤러가 아니라 FileController (/rest/api/v1/file/files) 쪽입니다.

5. 수정과 삭제

화면 함수HTTP서버
updateNotice(entityId, param)PUT /notice/notices/{entityId}경로 id를 엔티티에 심고 update. @Merge가 있는 필드만 반영되는 병합입니다.
deleteNotice(entityId)DELETE /notice/notices/{entityId}단건 삭제. 서비스가 같은 공지의 첨부 메타를 먼저 지운 뒤 공지 행을 지웁니다.
deleteNotices(entityIds)DELETE /notice/notices?entityIds=...여러 id. 부모 deleteAllBySearchParameter.

삭제 응답 본문은 비어 있습니다. 컨트롤러 반환 타입이 void입니다. 화면은 HTTP 상태만 보고 목록을 다시 조회하면 됩니다.

6. 다른 사람에게 알려야 할 때

목록 조회는 요청한 사람만 받습니다. “방금 공지가 등록됐다”를 다른 상담원 화면에 바로 띄우려면 웹소켓 토픽 /topic/regist-notice를 씁니다. 봉투는 FlowWebSocketMessage이고, 서버가 여러 대면 Redis 발행 → 각 인스턴스 구독 → 그 서버에 붙은 브라우저 순입니다. 자세한 연결은 스케줄러와 웹소켓에 있습니다. 공지 서비스는 기동 시 Redis 리스너 목록에 자신을 넣습니다.
