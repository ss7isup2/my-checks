1. CSS 규칙의 모양

CSS는 “어떤 요소를 찾아서, 그 요소의 속성을 어떤 값으로 둘지”를 적는 언어입니다. 한 덩어리를 규칙이라고 부릅니다.

.btn {
  height: 28px;
  background: #fff;
}
  • .btn는 선택자입니다. 클래스 이름이 btn인 요소를 찾습니다.
  • height는 속성, 28px는 값입니다. 속성과 값을 합쳐 선언이라고 합니다. 선언은 세미콜론으로 끝냅니다.
  • 중괄호 안이 선언 블록입니다.

브라우저는 HTML을 그린 뒤 스타일시트를 읽고, 각 요소에 맞는 선언을 모아 최종 스타일을 계산합니다. React의 className="btn primary"는 DOM에 class="btn primary"를 만듭니다. CSS는 React를 모르고 그 class 문자열만 봅니다.

이 프로젝트의 스타일은 CSS Modules가 아닙니다. 클래스 이름이 파일 전체에서 전역으로 통합니다. card라는 이름을 다른 뜻으로 다시 쓰면 화면 전체의 카드가 바뀝니다.

2. 선택자

선택자는 요소를 고르는 조건입니다. 이 파일이 실제로 쓰는 종류만 정리합니다.

3. 박스

화면에 놓이는 요소는 모두 사각형입니다. 안쪽부터 내용, padding, border, margin입니다.

  • width와 height는 기본적으로 내용 크기만 말합니다. padding을 더하면 눈으로 보는 크기가 더 커집니다.
  • box-sizing: border-box로 바꾸면 width 안에 padding과 border가 포함됩니다. 이 파일 1행 다음의 *가 모든 요소에 그 값을 줍니다. 그래서 입력칸에 width: 100%와 padding: 0 8px를 같이 줘도 부모 밖으로 넘치지 않습니다.
  • margin은 바깥 간격이라 width에 포함되지 않습니다. gap은 Flex와 Grid가 자식 사이에 넣는 간격이고, margin과 달리 부모 안에서만 계산됩니다.

display는 그 상자가 줄 안에서 어떻게 놓이는지, 자식을 어떻게 나누는지를 정합니다.

  • block은 한 줄을 차지합니다. div의 기본값입니다.
  • inline은 글자처럼 흐릅니다. span의 기본값입니다. width와 height가 잘 먹지 않습니다.
  • inline-flex와 inline-grid는 자신은 글자처럼 놓이면서 자식은 Flex나 Grid로 나눕니다. 알약 버튼이 이 방식입니다.
  • none은 이 파일에 없습니다. React가 요소를 렌더링하지 않는 방식으로 오른쪽 패널을 숨깁니다.

4. 상속과 덮어쓰기

어떤 속성은 부모 값이 자식에게 내려갑니다. 이 파일에서 그런 속성은 color, font-family, font-size, line-height입니다. :root에 12px를 주면 카드 안의 글자도 12px로 시작합니다. 제목은 자기 font-size로 그 값을 덮습니다.

background, width, margin, border는 상속되지 않습니다. 카드 배경을 흰색으로 적지 않으면 부모의 회색이 비쳐 보일 뿐, 카드가 흰색 속성을 물려받지는 않습니다.

폼 컨트롤은 예외입니다. button과 input은 글꼴을 상속하지 않고 브라우저 기본 글꼴을 씁니다. 25행의 font: inherit가 그 기본을 부모 글꼴로 되돌립니다. font는 font-size, font-family, font-weight 등을 한 번에 지정하는 단축 속성입니다.

한 요소에 같은 속성이 여러 규칙에서 오면 아래 순서로 하나를 고릅니다.

  1. 인라인 style 속성이 스타일시트보다 강합니다. 이 화면의 신뢰도 막대 <i style="width: 96%">가 그 예입니다. 너비는 JSX에 있고 CSS는 높이만 정합니다.
  2. 선택자가 더 구체적이면 이깁니다. 대략 클래스 하나가 요소 이름보다 강하고, 클래스가 많을수록 강합니다. .rail button.on은 클래스 둘과 요소 하나라 .rail button보다 강합니다. 그래서 선택된 아이콘만 파란 배경이 됩니다.
  3. 구체성이 같으면 파일에서 나중에 나온 선언이 이깁니다. .live-pill과 .time-pill은 둘 다 클래스 하나입니다. .time-pill이 뒤에 있어서 시간 알약의 배경만 회색으로 바뀝니다.
--orange는 11행에 만들어 두었지만, 이 파일 안에서 var(--orange)로 읽지는 않습니다. 주황 알약은 63행 근처에서 색을 직접 적습니다. 변수는 선언만으로 화면에 영향이 없습니다.

5. Flex와 Grid

둘 다 부모에게 display를 주고, 그 부모가 자식을 배치합니다.

Flex

자식을 한 방향 줄로 놓습니다. 기본 방향은 가로입니다. flex-direction: column이면 세로입니다.

  • justify-content는 주축 정렬입니다. 가로 flex에서는 좌우, 세로 flex에서는 위아래입니다. space-between은 첫 자식과 마지막 자식을 양 끝에 붙입니다.
  • align-items는 교차축 정렬입니다. 가로 flex에서 center면 세로 가운데입니다.
  • flex: 1은 남은 공간을 먹습니다. .grow가 제목과 버튼 사이를 밀어 냅니다.
  • flex: none은 줄어들지 않습니다. 서버 연동 막대가 카드 아래에 높이를 유지하는 이유입니다.
  • min-width: 0과 min-height: 0은 자식이 내용보다 작아질 수 있게 합니다. 이 값이 없으면 Flex와 Grid 자식은 글자 너비 아래로 줄어들지 않아 스크롤이 부모 대신 페이지에 생깁니다.

Grid

행과 열을 먼저 정하고 자식을 칸에 넣습니다. 자식은 HTML에 나온 순서대로 칸을 채웁니다.

  • grid-template-columns: 52px 300px 1fr 304px 32px처럼 적으면 왼쪽부터 그 너비의 열이 생깁니다.
  • 1fr는 고정 칸을 빼고 남은 공간의 한 몫입니다. 1.45fr 0.75fr이면 남은 공간을 1.45 대 0.75로 나눕니다.
  • auto는 내용이 필요로 하는 크기입니다.
  • minmax(0, 1fr)는 최소 0, 최대 남은 공간입니다. 최소를 0으로 둬야 긴 글자가 열을 억지로 넓히지 않습니다.
  • repeat(3, minmax(0, 1fr))는 같은 열을 세 번 만듭니다.
  • place-items: center는 Grid 칸 안에서 자식을 가로세로 가운데에 둡니다. 로고의 “우” 글자가 파란 사각형 한가운데에 있는 방식입니다.

이 화면은 큰 칸을 Grid로 나누고, 칸 안의 한 줄은 Flex로 나눕니다. .app이 헤더와 본문을 나누고, .body가 다섯 열을 나누고, .card-head가 제목과 버튼을 한 줄로 놓습니다.

6. 위치

  • static이 기본값입니다. 문서 흐름대로 놓입니다.
  • relative는 자기 자리를 유지한 채 기준점만 만듭니다. .icon-btn이 relative이고 그 안의 .dot이 absolute라, 빨간 점이 버튼 모서리를 기준으로 붙습니다.
  • absolute는 흐름에서 빠집니다. 뒤 요소가 그 자리를 채웁니다. 기준은 가장 가까운 relative, absolute, fixed 조상입니다. 없으면 페이지입니다. 오류 배너가 헤더 위에 겹치는 이유입니다.
  • fixed도 흐름에서 빠지고, 기준이 브라우저 창입니다. 스크롤해도 토스트가 창 하단에 남습니다.
  • left: 50%는 요소의 왼쪽 끝을 가운데에 둡니다. transform: translateX(-50%)가 자기 너비의 절반만큼 왼쪽으로 당겨 진짜 가운데가 됩니다.
  • z-index는 겹치는 순서를 정합니다. position이 static이 아닌 요소에서 동작합니다. 배너는 20, 토스트는 30이라 토스트가 더 위입니다.

9. 한 줄이 화면까지 가는 예

저장 버튼은 JSX에서 className="btn primary"입니다. 계산은 이렇게 겹칩니다.

  1. 27행이 모든 버튼의 커서를 pointer로 둡니다.
  2. 201행이 .btn이라 높이, 흰 배경, 테두리를 줍니다.
  3. 206행이 .btn.primary라 배경과 테두리와 글자색을 파랑과 흰색으로 덮습니다. 클래스가 하나 더 있어 201행보다 강합니다.
  4. 마우스를 올리면 204행 .btn:hover도 맞습니다. 이 선택자와 206행 .btn.primary는 구체성이 같습니다. 클래스 하나와 가상 클래스 하나가 클래스 둘과 같은 세기이고, 206행이 뒤에 있습니다. 그래서 주요 버튼의 테두리는 마우스를 올려도 파랑으로 남습니다. 흰 버튼만 204행의 테두리색을 봅니다.
  5. disabled가 되면 205행이 투명도를 낮춥니다. 205행은 배경색을 바꾸지 않으므로 206행의 파란 배경은 남고, 그 위에 투명도만 곱해집니다.

이 순서가 CSS를 읽을 때의 기본 순서입니다. 선택자가 누구를 고르는지 보고, 그 속성이 상속되는지 보고, 같은 속성을 적은 다른 규칙이 있는지 확인하면 됩니다.
