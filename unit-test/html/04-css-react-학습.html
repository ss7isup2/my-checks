1. CSS를 읽는 순서

브라우저에서 화면을 연 다음, 요소를 오른쪽 클릭하고 검사를 누릅니다. 오른쪽에 그 요소에 적용된 CSS가 나옵니다. 취소선이 있는 속성은 다른 규칙에 진 것입니다. 값을 그 자리에서 바꿔 본 뒤, 마음에 들면 src/styles/global.css에 같은 값을 적습니다. 검사 창의 수정은 새로고침하면 사라집니다.

파일에서는 한 규칙을 이렇게 읽습니다.

.app {
  height: 100vh;
  min-width: 1440px;
  display: grid;
  grid-template-rows: 52px minmax(0, 1fr);
  background: var(--bg);
}

.app이 누구를 고르는지, height가 그 상자의 키를 얼마로 두는지, 한 줄씩 말로 바꿉니다. “창 높이 전체, 최소 너비 1440px, 자식을 격자 두 줄로 나눈다.”처럼요. docs/html/03-css-설명.html의 줄 번호 표는 이때 사전으로 씁니다.

4. Flex와 Grid를 서로 바꿔 보기

큰 칸은 Grid가 나누고, 한 줄은 Flex가 나눕니다. 부모의 display만 바꿔도 자식 배치가 달라집니다.

대상바꿀 값결과
.toolsflex-direction: column모니터, 알림, 사용자 이름이 세로로 쌓입니다. 지금은 display: flex라 한 줄입니다.
.top의 1fr200px가운데 상태 알약이 남은 공간을 더 이상 먹지 않습니다. auto인 오른쪽 사용자 영역은 내용 너비 그대로입니다.
.body의 300px180px통합상담 열만 좁아집니다. 고객명과 접수현황이 답답해지면 그 숫자가 왼쪽 열이라는 뜻이 확인됩니다.
.body의 304px220pxAI Advisor 열만 좁아집니다. 키워드 칩이 다음 줄로 넘어갑니다.
.center의 348px220px고객여정 카드 높이만 줄어 타임라인이 그 안에서 스크롤됩니다.
.journey-toolsflex-direction: column채널 탭과 날짜 범위가 위아래로 나뉩니다. 지금은 왼쪽 탭, 오른쪽 날짜입니다.
.grow의 flex: 1이 규칙을 지운다접수현황의 “전체 2,462”가 제목 바로 옆으로 붙습니다. 빈 칸이 남은 가로 공간을 먹던 역할이 사라집니다.
.cols-41fr 1fr접수채널, 사번, 성명, 전화번호가 두 칸씩 두 줄이 됩니다.
.form-grid의 gap: 8px 10px24px 24px입력칸 사이만 넓어지고 칸 크기는 그대로입니다. gap은 자식 사이 간격입니다.

min-height: 0도 한 번 지워 볼 만합니다. .left에서 그 줄을 지우면 왼쪽 카드가 창 높이를 넘겨, 열 안 스크롤 대신 페이지가 늘어납니다. Flex와 Grid 자식은 기본으로 내용 높이보다 작아지지 않기 때문입니다.

5. 상속과 덮어쓰기

:root의 font-size: 12px를 16px로 키우면 대부분 글자가 커집니다. 그다음 .card-head h2의 13px는 자기 크기를 직접 적었기 때문에 16px를 물려받지 않고 13px로 남습니다. color도 상속됩니다. background, border, margin은 상속되지 않습니다. 카드 배경을 지우면 카드가 흰색 속성을 물려받는 것이 아니라, 뒤의 회색이 비칩니다.

폼 글꼴은 예외입니다. button, input, select, textarea { font: inherit }를 지우면 입력칸만 브라우저 기본 글꼴로 커집니다. 부모 글꼴을 따르라고 적어 둔 줄입니다.

같은 속성이 겹치면 저장 버튼을 보면 됩니다. 클래스 btn primary에는 .btn의 흰 배경과 .btn.primary의 파란 배경이 둘 다 해당됩니다. 클래스가 더 많은 .btn.primary가 이깁니다. 검사 창에서 .btn의 background에 취소선이 있으면 그 상황입니다.

.live-pill과 .time-pill은 클래스 개수가 같습니다. 파일에서 뒤에 있는 .time-pill이 배경을 회색으로 덮습니다. 두 규칙의 순서를 바꿔 보면 시각 알약까지 파란색이 됩니다.

6. CSS 하루 연습

  1. 검사 창에서 클래스 이름을 찾고 global.css에서 그 이름을 검색합니다.
  2. 숫자 하나만 바꿉니다. 색, 간격, 너비 중 하나입니다.
  3. 화면에서 어디가 바뀌었는지 한 문장으로 적습니다.
  4. 원래 값으로 되돌리거나, 더 나은 값이면 남깁니다.

순서는 색, 여백, 선택자, Flex, Grid, 위치 순서가 수월합니다. 위치는 .banner의 position: absolute와 .toast의 position: fixed를 서로 바꿔 보는 것으로 충분합니다. absolute는 문서 흐름에서 빠지고, fixed는 스크롤해도 창 기준으로 남습니다.

7. React가 화면을 다시 그리는 방식

React 화면은 “데이터가 바뀌면 그 데이터를 그리는 함수가 다시 실행된다”입니다. HTML을 직접 고치지 않습니다. 함수가 돌려주는 요소 나무가 이전과 다르면 브라우저 화면에서 그 차이만 바뀝니다.

App은 화면을 나누기만 합니다.

export function App() {
  return (
    <CounselProvider>
      <Shell />
    </CounselProvider>
  )
}

CounselProvider 안의 컴포넌트만 useCounsel()로 상담 데이터와 저장 함수를 쓸 수 있습니다. LeftPanel을 Provider 밖으로 옮기면 그 함수가 오류를 냅니다. 데이터가 어디까지 전달되는지 확인하는 실험입니다. 확인 뒤에는 원래 자리로 되돌립니다.

상태에는 두 종류가 있습니다.

  • useState는 그 컴포넌트 안에만 있습니다. 고객여정의 folded, 오른쪽 패널의 advisorOpen이 여기 해당합니다.
  • useCounsel()는 Provider가 가진 공통 상태입니다. 상담 한 건, 여정 목록, 선택 id, 저장 중 여부, 알림이 여기 해당합니다. 왼쪽 카드와 오른쪽 AI 카드가 같은 고객명을 보여주는 이유입니다.

입력칸은 화면의 글자를 직접 소유하지 않습니다. value={form.customerName}처럼 상태에서 글자를 받고, onChange가 새 글자를 상태에 넣습니다. 상태가 바뀌면 그 컴포넌트 함수가 다시 실행되어 입력칸에 새 value가 들어갑니다.

8. 클릭을 따라가 보기

접기

folded는 JourneyPanel 안에만 있는 값입니다. 버튼을 누르면 true와 false가 뒤집히고, 참이면 타임라인을 그리지 않습니다.

<button onClick={() => setFolded((value) => !value)}>
  {folded ? '펼치기' : '접기'}
</button>

{folded ? null : (
  <div className="journey-body">...</div>
)}

null은 그 자리에 요소를 만들지 말라는 값입니다. CSS로 숨기는 것과 달리, 접힌 동안에는 타임라인 버튼이 DOM에 없습니다. 검사 창으로 확인할 수 있습니다.

오른쪽 AI 패널

advisorOpen이 참일 때만 RightPanel을 그립니다. 가장자리의 AI Advisor를 누르면 그 값이 바뀌고, 클래스 이름도 body와 body advisor-closed 사이에서 바뀝니다. React가 상태를 바꾸고, CSS가 그 클래스에 맞춰 열 개수를 바꿉니다. 상태만 바꾸고 클래스를 그대로 두면 빈 칸이 남거나 열이 밀립니다. 두 파일이 짝이라는 점을 보는 실험입니다.

여정 행

visible.map은 배열 길이만큼 버튼을 만듭니다. 접점이 4개면 버튼이 4개입니다. 선택한 id와 같으면 클래스에 on이 붙어 파란 배경이 됩니다.

{visible.map((item) => (
  <button
    key={item.id}
    className={item.id === selectedId ? 'tl-item on' : 'tl-item'}
    onClick={() => selectTouchpoint(item.id)}
  >
    ...
  </button>
))}

key는 React가 목록에서 어떤 행이 어떤 접점인지 구분하는 이름입니다. item.id처럼 고유한 값을 씁니다. 전화 탭을 누르면 filter가 바뀌고 visible이 전화 접점만 남깁니다. 서버를 다시 부르지 않고, 이미 받아 둔 배열을 걸러서 다시 그립니다.

서버에 저장

처리내용의 글자는 SessionPanel의 form에 있습니다. 저장 버튼이 그 객체를 PUT /api/consultation으로 보냅니다. 성공하면 CounselContext가 상담 데이터를 응답 객체로 바꿉니다. 그 데이터를 읽는 왼쪽 고객정보와 오른쪽 AI 카드가 함께 다시 그려집니다.

고객명만 바꿔 저장해 보면 두 카드가 같이 바뀝니다. 입력칸을 고치는 동안에는 왼쪽 카드가 바뀌지 않습니다. 왼쪽 카드는 form이 아니라 서버에서 돌아온 consultation을 읽기 때문입니다. 이 차이로 “입력 중인 값”과 “저장이 끝난 값”을 구분할 수 있습니다.

접점 추가는 addTouchpoint가 POST를 호출하고, 응답 뒤 목록을 다시 읽은 다음 새 id를 선택합니다. 화면의 배열에 push하지 않습니다. 서버 목록을 다시 받아서 그 배열로 다시 그립니다. 삭제는 확인 버튼을 한 번 더 누른 뒤에 DELETE를 보냅니다.

9. 파일을 읽는 순서

새 컴포넌트는 아래 순서로 읽으면 화면과 연결됩니다.

  1. return 안의 JSX를 보고, 화면에 어떤 블록이 있는지 찾습니다. 제목, 버튼, 목록입니다.
  2. 그 블록에 적힌 {이름}이 어디서 오는지 위로 올라갑니다. useState인지, useCounsel()인지, 함수 인자인지 구분합니다.
  3. onClick과 onChange가 어떤 값을 바꾸는지 봅니다. 바꾸는 함수 이름이 set으로 시작하면 그 컴포넌트의 상태입니다.
  4. 서버 함수라면 src/api/client.ts에서 경로를 확인하고, CounselContext.tsx에서 응답을 어떤 상태에 넣는지 봅니다.
  5. 클래스 이름을 global.css에서 검색해, 그 상태가 붙일 때 색이나 배치가 어떻게 바뀌는지 봅니다.
