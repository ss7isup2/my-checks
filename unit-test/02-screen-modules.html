화면 모듈 설명

front-react 상담 화면을 구성하는 모듈입니다. 고객여정은 서버에서 목록을 가져오고, 추가·수정·삭제까지 하는 예시입니다. 상담 세션은 같은 방식으로 한 건을 조회하고 수정합니다.

1. 화면이 조립되는 순서

main.tsx가 App을 그리고, App은 CounselProvider로 화면 전체를 감쌉니다. 그 안의 Shell이 열을 배치합니다.

App
 └ CounselProvider          서버 상태, 저장, 알림
    └ Shell
       ├ TopHeader
       ├ IconRail
       ├ LeftPanel
       ├ SessionPanel        상담 수정
       ├ JourneyPanel        여정 조회·추가·수정·삭제
       │   └ TouchpointDialog
       └ RightPanel

2. 상태 모듈

CounselContext

src/state/CounselContext.tsx가 서버 데이터를 화면 공통 상태로 둡니다. 컴포넌트는 useCounsel()으로 같은 값을 읽습니다.

값의미
consultation현재 상담 한 건. 없으면 아직 조회 전
touchpoints고객여정 배열. 서버에 저장된 순서
selectedId여정에서 선택한 접점
log마지막 API 메서드, 경로, 상태 코드
saving저장 요청 중이면 버튼을 막습니다
notice / error성공 토스트와 실패 배너

조회에 실패하면 배너의 다시 시도가 reload()를 호출합니다. 추가와 수정이 성공하면 응답의 id로 목록을 다시 읽고 그 행을 선택합니다. 삭제 뒤에는 남아 있는 첫 접점을 선택합니다.

api/client.ts

모든 요청은 fetch이고 JSON을 주고받습니다. 상태 코드가 2xx가 아니면 서버의 message를 오류로 던집니다. 호출부는 상태 코드도 함께 받아 화면 하단 로그에 표시합니다.

3. 화면 모듈

TopHeader

로고, 전화·채팅·영상·메일·후처리 상태, 로그인 사용자입니다. 시안의 자리와 문구를 보여주는 표시 모듈이며 서버와 연결하지 않습니다.

IconRail

왼쪽 세로 아이콘입니다. 선택된 아이콘만 이 컴포넌트 상태로 기억합니다. 다른 업무 화면으로 이동하는 라우트는 이 예제에 없습니다.

LeftPanel

통합상담 열입니다.

  • 고객정보의 고객명, 연락처, 최근채널은 consultation에서 옵니다. 상담 폼을 저장하면 이 카드도 바뀝니다. 최근문의 문구는 시안의 “수납계좌 조회”를 유지합니다.
  • 접수현황과 금일 나의실적은 src/data/screen.ts의 고정 숫자입니다.
  • 최근여정도 시안 문구 세 줄입니다. 아래쪽 고객여정과 일부러 분리했습니다. 서버에서 지운 접점이 이 요약 목록까지 지우면 시안과 달라지기 때문입니다.

SessionPanel

상담 세션 카드입니다. 서버에서 받은 상담을 폼 상태로 복사하고, 사용자가 고친 값을 다시 서버에 보냅니다.

  • 저장은 현재 접수 상태를 유지한 채 PUT /api/consultation을 호출합니다.
  • 단순종료, 이관, 상담완료는 sessionStatus를 그 문구로 바꾼 뒤 같은 API로 저장합니다. 카드 오른쪽 알약 문구가 함께 바뀝니다.
  • 이어받기는 상담원 칸에 “관리자”를 넣습니다. 저장을 눌러야 서버에 남습니다.
  • 전화접수 탭은 같은 상담의 접수번호, 고객, 문의내용을 읽기 형태로 보여 줍니다.
  • 확장조회, 챗봇, 원격, 고객정보등록, 호전환, 부서 찾기는 이 예제의 범위 밖이라 안내 문구만 띄웁니다.

JourneyPanel — 조회, 수정, 삭제 예시

고객여정이 서버 연동 예시입니다. 카드 하단에 마지막 요청이 표시됩니다.

화면 동작호출결과
화면을 연다GET /api/touchpoints시간 순이 아니라 서버 배열 순서대로 타임라인에 표시
접점 추가POST /api/touchpoints새 행이 목록 맨 앞에 생기고 선택됨. 상태 코드 201
수정PUT /api/touchpoints/{id}제목, 요약, 상담내용, 처리결과 등을 바꿈
삭제DELETE /api/touchpoints/{id}확인 후에 삭제. 없는 id는 404
초기화POST /api/reset상담과 여정을 seed 값으로 되돌림

전체, 전화, WEB, SMS 탭과 날짜 범위는 받아 둔 배열을 화면에서 거릅니다. 발생일시가 YYYY-MM-DD HH:mm이면 저장할 때 타임라인의 날짜와 시간을 그 값에서 다시 만듭니다.

제목이 비어 있으면 화면과 서버가 모두 거절합니다. 서버 메시지는 “제목을 입력해 주세요.”입니다. 채널은 전화, WEB, SMS만 저장하고 그 외 값은 전화로 바꿉니다.

TouchpointDialog

추가와 수정이 같은 대화상자입니다. 추가일 때는 제목에 POST 경로를, 수정일 때는 해당 id의 PUT 경로를 보여 줍니다. 수정 모드의 삭제는 버튼이 “삭제 확인”으로 바뀐 뒤에 요청을 보냅니다.

RightPanel

AI Advisor, 지식 추천, 추천 답변, AI 요약입니다. 지식 목록과 답변 문장은 screen.ts의 시안 예시입니다. 답변 복사는 브라우저 클립보드에 그 문장을 넣습니다.

다음 값은 저장된 상담을 따라갑니다. 상담을 저장하기 전에는 폼에만 있고, 저장 후에 이 카드가 바뀝니다.

  • 고객명
  • 상담유형: 대분류 > 중분류 > 소분류
  • 키워드의 오류코드, 거래코드
  • 조치 문장. 처리내용이 있으면 그 문장, 없으면 시안의 기본 문장

오른쪽 닫기 버튼과 가장자리의 AI Advisor 글자는 이 열을 접고 펼칩니다. 서버 요청은 없습니다.

4. API 모듈

server/apiPlugin.mjs가 JSON 파일을 읽고 씁니다. 상담 id는 요청으로 바꾸지 못합니다. 상담 수정은 허용된 필드만 반영합니다.

메서드경로본문응답
GET/api/health없음{ "ok": true }
GET/api/consultation없음상담 객체
PUT/api/consultation상담 객체저장된 상담
GET/api/touchpoints없음접점 배열
POST/api/touchpointsid 없는 접점생성된 접점, 201
PUT/api/touchpoints/{id}접점 필드수정된 접점
DELETE/api/touchpoints/{id}없음삭제된 접점
POST/api/reset없음seed 전체

상담 객체의 주요 필드

id, channel, employeeNo, customerName, phone, receiptNo, department, receivedAt, agentName, requestType, categoryLarge, categoryMid, categorySmall, txCode, txName, txAction, errorCode, programName, userRequest, inquiry, handling, sessionStatus, sessionStartedAt.

접점 객체의 필드

id, dateLabel, timeLabel, channel, title, summary, statusLabel, occurredAt, consultType, content, result, processStatus.

실패 응답은 { "message": "..." }입니다. id에 영문, 숫자, _, - 외의 문자가 있으면 400을 반환합니다.

5. 예시로 따라 하는 수정과 삭제

상담 수정. 처리내용에 안내 문장을 적고 저장을 누릅니다. data/db.json의 consultation.handling이 그 문장으로 바뀌고, 오른쪽 요약의 조치 칸도 같은 문장을 보여 줍니다.

여정 추가. 접점 추가에서 제목 “테스트 접점”, 발생일시 2026-09-30 16:40을 저장합니다. 타임라인 맨 위에 09.30 16:40 행이 생깁니다.

여정 수정. 그 행의 수정을 눌러 처리결과를 바꿉니다. 오른쪽 선택 접점 상세가 서버에서 다시 읽은 값으로 갱신됩니다.

여정 삭제. 삭제 후 확인을 누르면 행이 사라지고 다음 접점이 선택됩니다. 초기화를 누르면 시안의 네 건으로 돌아갑니다.
